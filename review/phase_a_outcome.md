## 0. 先说结论

1. **A 的三项已落地并默认开启**（RAG_STRUCTURED=1，设为 0 可整体回退到旧路径）：
   - 金标页码解析修复 + 全量重算（指标层，不花钱）；
   - 出处由程序渲染：模型不写页码，结构化路径伪造不了；agent 路径逐句把出处归到证据页；
   - 答案结构化：claims + 逐条数字校验 + 受控计算器（脚手架，本次未触发）+ 一次修复重试。
2. **检索层的 66%→76% 是“尺子”修正，不是系统变强**：检索代码一行未改，改的是 gold 页码解析。Phase A 不宣称检索提升；任何把 66% 和 Phase A 后指标并列的写法都是口径混用。
3. **答案层（45 道可答题，同一套指标重算）**：
   - 答案正确率 **57.8% → 57.8%**（0pp，26/45 对 26/45）；
   - 引用精确率：两套都有引用的 **41 题配对 63.0% → 62.4%**（−0.6pp，持平）；原始均值 60.1%（43 题）/62.4%（41 题），分母不同不能直减；
   - 引用覆盖 any **73.3% → 66.7%**（−6.6pp）、all-gold **60.0% → 53.3%**（−6.7pp）；
   - 误拒答 **8.9% → 8.9%**；无答案题 **5/5 拒答**（两套一致）。
   - 分路径看，增益集中在直通题、代价集中在 agent 题（见 §3）。
4. **机制收益比指标更重要**（这是 A 的真正目的）：
   - 引用页越界：旧路径 2/43 份作答引用了检索集外的页；新路径 **0/41**（机器渲染出处与复检脚本都是 0；解析器修空格后，正文里的「2025 年报（P57）」也不会再算错年份）；
   - 未接地数字：用同一条检查规则，旧答案 23 个数字在检索证据里找不到且**无任何标记**；新答案检查器标出 35 个，其中 31 个真实图表数字全部写入 violations，另 4 个是“1.”“2.”列表序号被误判、管线本身未记；
   - 计算：受控计算器与 calculation 字段已就位、单测覆盖；本次 50 题模型全部按“抽取”作答，未触发计算路径；agent 路径里模型自算的派生数在归属时被排除，不再误报。
5. **不夸大**：50 题、单次运行，±2–3 题就能翻转 4–7pp；直通路径已做到确定性（同一配置两次 run 的 22 道直通题答案逐字相同），agent 路径仍有 ±2 题波动。因此本报告只给点估计与区间感，不做显著性声明。

**解读**：
- 直通路径（确定性，temperature=0）answer_correct / cite_any / all_gold 三项上升，精确率持平（配对 20 题两侧都是 67.5%），是 A 唯一干净的增益样本。
- agent 路径的 citation 覆盖下降不是“引用变少”，而是**归属变严**：模型原来会把整段答案挂在 gold 页上，但该页并不包含段落里全部数字；逐句归属后只保留“这页确实有这个数”的出处，剩下的数字进 violations。**精确率大体持平、覆盖率降**是同一个机制的两面。
- agent 路径的 answer_correct 下降 2 题处在噪声内：同一配置的第二次 run（v7）agent 正确率 52.2%，两次差 1 题；且 agent 仍用 temperature=0.1，本身不可复现。

## 3. 机制实测：校验器到底拦住了什么

以下例子均来自最终 run 的落盘结果（results/phase_a_structured.json）。

### 3.1 出处由程序渲染

- 直通题（27 题）：模型输出 claims，evidence 用 E1/E2 指代；render() 把 evidence 映射成「2024年报 P8」，模型无法写页码。构造测试里模型写 [来源: 2024年报 P999]，渲染时被剥离。
- agent 题（23 题）：模型自由文本里的 [来源: …] 先删除，attribute_text() 按句把数字对到「页」（同页多块合并），再加出处。q41 的两句话分别有 2023、2025 两个年份的数字，各自带出处「2023年报 P17」「2025年报 P10」。
- 整页校验：page_map() 把同一页的多个 500 字片段拼成整页再核对数字。本次 50 题里**没有找到“只有整页才能通过”的样本**（抽查 q1 的 16.53% 就在被检索到的块里），它的行为由单测覆盖；收益要更多样本才能验证，但能避免“表格被切开”造成的误报。

### 3.2 数字与计算

- q1（2022 营收）：第一版校验用模型自报的数字清单（写成「16.53」不带 %，与原文「16.53%」对不上）→ 误报；改为从 claim 文本抽取数字后通过。校验对象必须是用户读到的文本，不是模型自报的清单。
- q2（i茅台）：旧答案 3000万/118.83亿/95.26% 等数字无标记；新路径 7 个数字里 4 个未接地，全部写入 violations（95.26%、2,237,432.35万元、88.29%、96.09%；后两个来自未检索到的表块），答案带「部分内容未通过自动核对」提示。
- q10（销售费用增加额）：1,350,889,394.88 是两期相减的派生数；本次走 agent 路径，模型自算并在答案里写「（计算得出）」，归属时按规则排除这类数字，不再误报。结构化路径的 calculation 字段本次未被模型使用（见 §5 第 8 条）。
- 复检脚本把渲染后的列表序号「1.」「2.」也当数字，所以 35 个里有 4 个是序号；这 4 个不在管线的 violations 里（管线校验的是 claim 文本，不含渲染序号），真实图表数字仍是 31 个。

### 3.3 数据：同规则复查（两套答案都过同一条检查器）

| 项 | E9 | Phase A | 说明 |
|---|---|---|---|
| 数字总数 | 112 | 162 | 新答案更长、带同比/占比等补充 |
| 检索证据里找不到的数字 | 23 | 35 | 新答案基数大；31 个真实数字全部登记，4 个为复检噪声（旧路径 23 个无登记） |
| 有未接地数字的题 | 31.1% | 40.0% | 同上 |
| 引用页不在检索集的题 | 2/43 | 0/41（机器出处） | 旧：q19、q44 等；解析器修空格后（「2025 年报（P57）」也认得出），q44 正文页码不再算错 |

这条对比说明的是**可检测性**，不是“新答案更少幻觉”：新答案暴露了更多数字，其中 31 个真实数字一个不漏地记录；旧答案的 23 个数字无人知晓。

## 5. 已知问题与不做的事（避免下一轮踩坑）

1. **检索漏页直接造成假拒答**：q11（在职员工 33,302，P32）、q14（归母净利润，P5）、q19（员工 34,750，P33）、q24 等，检索到的 top-5 根本没有 gold 页；模型拒答是**正确行为**，修答案层无用。q44/q45 是 agent 工具没找到 P6/P19，属工具选参问题。
2. **answer_correct 的定义缺陷仍在**：它要求 gold 注释里的全部数字都出现，奖励“把注释里的数字都抄上”，与“是否答对所问”只有相关性。E8 审计里 16/26 的“错”答案其实答对了所问指标；本报告用它只为与历史结果对齐。
3. **引用指标对“同一数字出现在多页”敏感**：归母净利润同时出现在 P5（主要会计数据）和 P64（财务报表），模型引 P64 会被算错，尽管 P64 确实有该数。gold 页是“人工选定的那一页”，不是“唯一正确页”。
4. **整页校验依赖切块完整**：切块阶段丢了 2.5% 行（含 201 行正文，见原评审），被丢的行如果正好是某个数字，会误报“找不到”。当前只影响少量题。
5. **agent 路径仍不可复现**：temperature=0.1、工具轮次依赖模型；同配置两次 run 的 agent 正确率 56.5% vs 52.2%。
6. **没有判官、没有人工复核**：faithfulness 5.0/5.0 的问题原评审已说清，本次未重跑；引用与数字只做确定性校验。
7. **未做的**：lookup_metric / compare_metric / find_text 工具、文档 schema 的 document_id/collection_id、多公司 collection，这些属 B/C 阶段，本次未动。
8. **计算路径本次未触发**：50 题全部按 extract claim 作答，calculation 为空、calc_note 全空；受控计算器只有单测覆盖，尚未在真实题目上验证（B2 补）。
9. **page_map 的收益未在本次样本中体现**：没有找到“只有整页才能通过”的样本；它的行为由单测覆盖，需要跨块表格样本才能验证收益。
10. **解析器空格修复（2026-11-06）**：parse_sources 现在容忍「2024 年报」这种写法；修完后重跑了 score 与 rescore。v1 的结果文件已被覆盖，其精确率无法用新口径复算，§2.3 中 v1 保留当时的数字。
