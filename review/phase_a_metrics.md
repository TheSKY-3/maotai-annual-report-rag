## 1. 一句话结论

- 生产检索 hit@5：**66.0% → 76.0%**（+10.0pp，n=50）。
- 跨页题 hit@5：**40.0% → 90.0%**（+50.0pp，n=10）。
- 原因不是检索变强了，是**金标出处标少了**：`2024年报 P9、P16` 这类写法只解析出 P9，P16 被静默丢掉，于是「只命中一页」被算成未命中。

## 9. 旧口径的可复现性对账

为了证明「旧口径」不是本文编的，脚本对每一题都做了复算对账：

| 对账项 | 结果 |
|---|---|
| 带落盘指标的文件 | 27 个 |
| 其中落盘值逐题都能被旧算法解释（即旧口径 = 落盘值） | 27/27 |
| 落盘 `gold_pages` = 修复前正则解析结果 | 0 题不一致 |
| 落盘 `page_hit` = 用落盘旧 gold 重算 | 0 题不一致 |
| 落盘 `cite_correct` = 旧口径重算 | 0 题不一致 |
| 落盘 `answer_correct` = 原定义重算 | 0 题不一致 |
| 疑似生成于修复之后（落盘值其实是修正口径） | 0 个 |

最后一行是关键前提：只有当文件生成于修复**之前**，落盘值才算旧口径。脚本按「落盘值更贴合旧算法还是新算法」自动判定，一旦某个 run 是修复后重跑的，它会被点出来而不是被误当旧口径。

## 10. 影响面与后续动作

1. **不需要重跑检索**：`got_pages` 是当时真实的召回证据，本次只改 gold 解析，重算后的数字就是这些 run 的修正成绩。
2. **需要更新对外数字**：README / report 里引用 66% 一类数字的地方应改为本次修正口径的值（本文档不改 README 与 report）。
3. **CI 阈值需要重新标定**：`scripts/ci_retrieval_gate.py` 的 `THRESHOLD = 0.64` 是按旧口径 66% 减 2pp 定的；修正后生产基线抬到 76.0%，闸门会放过约 12pp 的静默回退，应同步上调。
4. **答案层缺逐题召回证据**：答案层 run 没落 `got_pages`，只能重算引用口径；要拿到答案层 hit@5 需在评测脚本里补落盘。
