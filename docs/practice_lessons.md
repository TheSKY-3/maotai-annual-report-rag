# 实践踩坑与解法留痕

记录日期：2026-11-13。范围：接地校验与坐标核验两个缺陷的修复、本轮被实测
否决的三条提升路线、以及判分口径的两次纠错。

目的有两个：一是让修复可复查（每条都带文件行号与验证命令），二是把
"这类工作会踩什么坑"留下来，避免下次重复投入。

体例参照 `docs/deploy_local_linux.md`（部署踩坑权威留痕）。

## 一、已修缺陷

### 缺陷 1：接地校验用子串包含，模型自算的数被当成原文引用

**现象。** 答案里出现年报上没有的百分比，系统不报警、不要求标注
「计算得出」，读者以为是原文数字。实测三例：id31 `10.51%`、
id39 `34.92%`、id40 `6.52%`。

**根因。** `src/ask.py` 的 `ungrounded_numbers` 原实现把语境压成无空格
字符串，再判 `答案数字 in 语境`。于是：

```
答案 10.51%   语境含 110.51   → "10.51" 是 "110.51" 的子串 → 判为已接地
答案 34.92%   语境含 1,234.92 → 同理 → 判为已接地
```

校验没报警，`_grounding_fix` 的修正重试就不触发，标注也就不会补上。

**顺带发现的第二个错。** 原实现的单位换算靠枚举字符串形态
（`×1e4 / ×1e8 / ÷1e4 / ÷1e8`）做精确匹配。答案写「1,741.44 亿元」、
原文是 `174,144,069,958.25`，换算形态 `174144000000` 在原文里凑不上，
于是**真接地反被误报**。四舍五入过的亿元数几乎必中此坑。

**修法。** 复用项目里已有的正确实现，不新写比对逻辑：

- 抽数 → `claims.citation_spec`（剥出处标注、列举序号、跳过年份）
- 比对 → `numeric.find_number`（按 token 比、单位归一、0.2% 容差、
  表头「单位：X」还原裸数字）

删除只被该函数使用的 `_NUM_RE` / `_CITE_RE` / `_flat_digits`。

**验证。**

```
.venv/Scripts/python.exe -X utf8 -m pytest tests/test_grounding_check.py -q
→ 14 passed（修复前 8 failed / 6 passed）
```

覆盖：三例子串假接地必须抓到；亿元↔元、万元↔元、表格单位声明、
百分数↔表格裸数四类真接地不许误报；出处页码/列举序号/年份不算答案数字；
返回值保留单位写法。

**生产影响已验证**——校验收紧会改变生产答案，留出集 150 题复跑结果见
第六节：转错 0 题、拒答 15/15 不变，无回退。

**端到端探查（3 道已知缺陷题，走 answer_auto，约 ¥0.02）。**

| 题 | 改前 | 改后 |
|---|---|---|
| id40 | 多出「国外同比下降 6.52%」，2025P17 上 0 处命中 | 该句消失，改为表格 + 口径说明 |
| id31 | `同比减少10.51%`，无标记 | `同比（%）为 -10.51`，带符号、是表内原值 |
| id39 | `34.92%`，无标记 | `同比为 -34.92%`，同上 |

**残留问题（本轮未修，属另一件事）。** 亿元换算值如「约222.75亿元」
仍未标「计算得出」。原因：接地校验按 0.2% 容差把单位换算视为已接地，
不触发修正重试，标记补不上；而 `cite_locate.locate_number` 不做单位
换算，这些数照样框不出来。即**缺陷 2 的前端修复只覆盖"已标记"的计算值，
未标记的换算值仍会漏进红框**。要治本得让换算值一律标记，或让坐标定位
支持单位归一——两者都超出本轮批准范围，记此待议。

### 缺陷 2：前端把已标「计算得出」的数送进红框

**现象。** 出处卡写着「坐标核验 · 红框 = 答案引用的数字」，但答案里
换算出来的亿元数在图上没有红框。读者以为系统坏了。

**根因。** 后端早已诚实标注（`src/ask.py` 的修正提示要求标「计算得出」，
`src/claims.py` 还会给只含计算值的句子反推成分页）。前端
`web/src/api.ts` 的 `answerNumbers` 抽数字时**不看这个标记**，把计算值
一并塞进 `/cite_crop` 请求。纸上没有的数当然框不出来——**界面承诺了
一件做不到的事**。

**修法。** `answerNumbers` 改用 `matchAll` 拿到位置，检查该数字之后
40 字符内是否出现「计算得出」，命中则跳过。截断规则：遇到下一个数字或
`[来源` 就停，避免把邻近别的数的标记错记过来。认两种写法：
`（计算得出）` 与 `（约425.96亿元，计算得出）`。

**验证。** 单元测试 + 真浏览器肉眼核验，两者都做。

```
cd web && ./node_modules/.bin/vitest run   → 60 passed
```

浏览器核验（独立端口 5173 的 dev server，代理到常驻 8000，
**未改动常驻服务**）。点预设⑤「2025年营业总收入比2022年增长了多少？」：

```
答案   … = 44,500,212,534.94 元（计算得出），增幅约 34.89%（计算得出）
改前送进红框  172,054,171,890.91 / 127,553,959,355.97 /
              44,500,212,534.94 / 34.89%      ← 后两个永远框不出来
改后送进红框  172,054,171,890.91 / 127,553,959,355.97
三张坐标图    naturalWidth 均为 1240，complete=true（真渲染，不是占位）
```

## 二、本轮被实测否决的三条路（别再重复投入）

### 1. 表格输出形态：不值得做

调参集 15 题（跨页 10 + 跨年 5），本次对照专用口径：

| | 自然语言（现状） | 指标对比表 |
|---|---|---|
| 数字命中 | **33/39 = 84.6%** | 17/39 = 43.6% |
| 全对题数 | **9/15** | 5/15 |
| 原文引用定位 | 47/53 = 88.68% | 18/18 = 100% |
| 指标表覆盖 | — | 10/15 |

表格唯一的优势是定位自洽、歧义 0，代价是信息量掉一半、三分之一的题
清单里没有对应指标。**不做。**

边界要说清：本实验测的是**单公司 × 双年 × N 指标**。Hebbia 的 Matrix
View 是**多文档 × 多字段**，价值在跨文档，本实验不足以否决那种形态。

复现：`scripts/compare_output_forms.py`，结果 `results/form_compare.json`。

### 2. 交叉编码器精排：早就测过，更差

`src/hybrid.py:155` 的 `RerankedRetriever` 是完整实现，生产没挂。
**这不是遗漏，是 deliberate 决定**，`src/pipeline.py:10` 写明了原因。

调参 50 题修正口径（`review/phase_a_metrics.md:62-64`）：

| 配置 | hit@5 | all@5 |
|---|---|---|
| E3 精排 | 70% | 60% |
| **E5 语境增强（生产）** | **76%** | **60%** |
| E5 + 精排 | 72% ↓ | 58% ↓ |

`review/eval-audit.md:89` 的符号检验：E5 → E5_rerank −2pp，5 胜 4 负，
p=1.0000，判为噪声。且精排每次查询约多 2 秒。

### 3. 表格结构化解析：三个变体全部更差

同一份报告（`review/phase_a_metrics.md:65-67`）：E7 表格 56%、
E7b tableplus 66%、E7c ctx_table 60%，全部低于生产的 76%。

另外核查了那个"已建好未启用"的产物 `data/chunks/contextual_table.jsonl`
（2026-11-02，比生产索引早 9 天），**不能直接切上去**：

- 只有 105 块带【表格】标记，样本是词语释义表，线性化错乱：
  `上交所：指 指；中国证券监督管理委员会 上海证券交易所`
- 核心财务报表（2024P63 合并利润表）在该变体里**仍是拍平文本**，
  与生产一字不差，年份列没有标签

### 4. 按题型分配召回：本轮新试，无效

跨年题每年各召回 top_k 再轮转合并，保证两年都有名额。

| | hit@5 | all@5 |
|---|---|---|
| 调参 50 题 生产 | 86.00% | 68.00% |
| 调参 50 题 本策略 | 86.00% | 70.00%（+1 题） |
| 留出 150 题 生产 | 77.33% | **67.33%** |
| 留出 150 题 本策略 | 77.33% | **66.67%**（−1 题） |

调参上的增益在留出集反向 → 噪声，**不上生产**。

复现：`scripts/run_recall_alloc.py`（纯本地零 API），
结果 `results/recall_alloc_tuning.json` / `recall_alloc_holdout.json`。

## 三、判分尺子的两次纠错

**指标难看时，先查尺子是否公平，再查产品。** 本轮两次都是尺子的问题。

### 纠错 1：把已诚实标注的计算值当成定位失败

原口径「自洽定位率 47/72 = 65.28%」把答案里标了「计算得出」的数也
要求能在纸上定位。那些数本来就不在纸上，**扣分扣的是模型的诚实，
不是产品的缺陷**。

改为双口径并列（`scripts/compare_output_forms.py` 的 `summarize`）：

- 自洽定位 47/72 = 65.28%（原口径保留，可追溯）
- **原文引用定位 47/53 = 88.68%**（扣除 19 个已标计算值）

与历史坐标定位水位 90.24% 同一量级，说明现状并不差。

重算不重新提问、零 API：

```
.venv/Scripts/python.exe -X utf8 scripts/compare_output_forms.py \
    --rescore results/form_compare.json
```

### 纠错 2：快速探查的正则没截断，把隔壁数的标记错记过来

第一次手工探查用「该数字之后 40 字符内有没有『计算得出』」，得出
22 个已标、定位率 94.00%。**这个数是错的。** 反例：

```
销售收入为 2,002,366.62 万元（约200.24亿元（计算得出））
           ↑ 原文引用数        ↑ 标记属于这个换算值
```

不截断就会把换算值的标记记到原文数头上。正式实现加了「遇到下一个数字
或 `[来源` 就停」，得到 19 个已标、88.68%。**94% 已撤回。**

同类问题在生产也存在：`src/claims.py:448` 的 `_CALC_NUM_RE` 只认
`（计算得出）`，不认 `（约X亿元，计算得出）` 的逗号写法。本轮未改
（超出批准范围），记在这里待议。

## 四、这类工作会踩的坑（方法论）

1. **"现成代码没接线"不等于缺口。** 先查实验记录与模块 docstring。
   本轮把精排当成"最便宜的检索提升"推荐出去，查了
   `review/phase_a_metrics.md` 才发现早测过且更差。表格解析同理。

2. **小样本的分题型数字会误导诊断。** 调参集跨年题只有 5 道，
   all@5 20% 看着像重病；留出集 15 道实为 66.67%，并不差。
   照着 5 道题的结论去设计策略，靶子就打偏了——留出集真正弱的是
   **跨页题 all@5 46.67%（30 题）**，而该策略完全没碰它。

3. **子代理报告必须复核。** 本轮盘点报告有两处错：
   说 `violations`/`degraded` 被 API 丢弃（实际 `src/api.py:192-195`
   明确声明了，丢的是 `claims`/`calc_note`）；说表格结构化产物
   "已写好未启用"暗示可直接切换（实际产物更旧且线性化错乱）。

4. **环境性假失败别当回归。** 全量测试曾报 7 failed，全在
   `tests/test_api_backend.py`，根因是 shell 的 `NO_PROXY` 含 IPv6
   `::1`，httpx 把它当 URL 解析抛 `InvalidURL`。单次调用前
   `unset NO_PROXY no_proxy` 后 14 passed、全量 235 passed。
   **没有改用户任何配置。**

5. **多口径数字不可混用。** `README.md:485` 的 91.9% 是 holdout_v3
   （124/135）；磁盘上 `results/holdout_answer_rescore.json` 是
   holdout_cloud（123/135 = 91.11%），**不是同一次 run**。
   对外报数必须说清是哪次、哪套口径。

6. **选型只在调参集做，留出集只验证一次。** 本轮四个配置在调参 50 题
   上比较，选定后留出 150 题只跑 prod 与选定配置两个，不在留出集上
   挑最好的。

7. **对照实验的返回条数必须锁死。** 检索策略若返回超过 top_k，
   hit@k 会被刷上去——那不是检索变好，是尺子被改了。
   `tests/test_per_year_recall.py` 专门锁了这条 invariant。

8. **要不要重跑付费评测，看改动进没进生产。** 检索那次策略只写在
   `scripts/` 的实验包装器里、从没接进 `src/pipeline.py`，否决即丢弃，
   系统行为不变，不必重考。接地校验改的是 `src/ask.py`，位于生成路径上，
   答案会真的变（id31/39/40 三题实测已变），所以必须复跑留出集。
   判据是"生产行为是否改变"，不是"改了哪个目录"。

9. **涨了一题先看是不是已知波动题。** 本轮 91.85%→92.59% 的唯一来源是
   id227，而它在项目记录里就是易波动题。不做多次 A/B 就宣称提升，
   等于把噪声当成果。
