# 茅台年报 RAG 项目实施计划

## 一、背景与目标

在 `D:\eng_project\rag项目` 下，基于贵州茅台 2022–2025 年年报（4 份 PDF，556 页，已从巨潮资讯网下载并验证）搭建一套**可评测、带引用出处**的知识库问答系统。全程用通俗中文记录在 LaTeX 报告（含图表），最终编译成 PDF。项目定位：面向个人投资者与研究者的年报问答助手——自然语言提问，答案必带原文出处，效果由 50 题评测集量化验证。

## 二、环境实况（已探查确认）

- 硬件：RTX 5070（12GB 显存）+ 32GB 内存 —— 本地跑 4B~8B 模型无压力
- Python 3.12.10，仅 pypdf 已装；chromadb / sentence-transformers / torch / matplotlib / ragas / streamlit / openai 均未安装
- **Ollama 未安装，本机无任何本地模型**（用户记忆中的 qwen3.5 2B 不存在，需安装）
- LaTeX：无 xelatex/pdflatex，但 **tectonic 0.17.0 可用**（内置 XeTeX，配 ctex 宏包可编译中文 PDF，首次编译联网下载宏包）

## 三、技术栈

| 环节 | 选择 | 说明 |
|---|---|---|
| 生成模型（主力） | Ollama + Qwen 本地模型 | 先尝试 `qwen3.5:2b`（用户提的名字），库里若无则用 `qwen3:4b` 或 `qwen2.5:7b-instruct`（12GB 显存按实际占用选） |
| 生成模型（对比） | DeepSeek API | 仅用于 E4 对比实验和 ragas 评分裁判，费用几块钱以内，需用户注册 key |
| Embedding | BGE-small-zh-v1.5（本地 CPU） | 本语料规模 CPU 足够快；**torch 装 CPU 版**，避免 RTX 5070（Blackwell 架构）的 CUDA 12.8 轮子兼容问题 |
| 向量库 | Chroma（本地持久化） | |
| 检索 | 向量检索 → 混合（BM25+向量）→ bge-reranker-base 精排 | 三档渐进，对应实验 E2/E3 |
| 评测 | ragas + 自建 50 题黄金集 | 裁判模型默认 DeepSeek（分数可信、费用低） |
| 界面 | Streamlit | 对话 + 引用展开 + 年份对比 |
| 报告 | LaTeX(ctex) + matplotlib 图表 + tectonic 编译 | |

## 五、实施阶段（每阶段有验收标准）

**阶段 0 · 环境搭建**
- 建 venv，安装依赖（torch 用 CPU 版；ragas/langchain 相关固定版本避免兼容问题）
- 安装 Ollama（winget 或官网安装包），拉取本地 Qwen 模型，验证 OpenAI 兼容端点可用
- 写一个最小 ctex 测试文档用 tectonic 编译通过（首次编译需联网下宏包）
- 验收：`ollama run <model>` 正常回答；测试 PDF 正常出中文

**阶段 1 · 最小 RAG 跑通**
- `scripts/extract_text.py`：pypdf 逐页提取 → `data/extracted/{year}/page_XXX.txt`，元数据含年份+页码（引用溯源的根基）
- 切块：约 500 字/块、重叠 100 字，每块带 {year, page}
- BGE 向量化 → 存入 Chroma
- `src/ask.py` 命令行问答：检索 top5 → 拼 prompt（要求带出处、查不到就明说）→ 本地 Qwen 生成
- 验收：问“2024 年茅台营业总收入是多少”答对且出处正确；问年报里没有的事会承认查不到

**阶段 2 · 黄金问答集（50 题）**
- 构成：30 简单事实题 / 10 跨页跨表题 / 5 跨年份对比题 / 5 无答案题
- 流程：subagent 从提取文本起草原稿 → 用户人工核对答案与页码（茅台数字有大量新闻可交叉验证）
- 格式：`data/gold/questions.jsonl`，字段 question / gold_answer / source / type

**阶段 3 · 评测基线**
- ragas 四指标：忠实度、答案相关性、检索精确率、检索召回率 + 自定义“无答案题拒答率”
- 产出 `results/baseline.json` + 第一张评测图

**阶段 4 · 实验矩阵**（同一评测集，见第六节）

**阶段 5 · Streamlit 界面**
- 对话框 + 每条答案下方挂出处（年份+页码+原文片段，可展开）
- “对比模式”：选两个年份生成指标对比表（展示跨文档检索能力）
- 拉伸目标（可选）：FastAPI 暴露 /v1 检索接口

**阶段 6 · LaTeX 报告 + 编译 PDF**
- 见第七节章节结构；matplotlib 画图（中文用微软雅黑字体）
- `tectonic report.tex` 编译；渲染成 PNG 后派 visual-judge 子代理做视觉验收，修复后再交付

## 六、实验矩阵（“做了什么对比、有什么结果”的答案）

| 实验 | 对比 | 预期能讲出的结论 |
|---|---|---|
| E1 切块策略 | 固定 500 字 vs 按标题结构切块 vs 父子块（小块检索、大块喂模型） | 结构化切块对表格密集文档的召回提升 |
| E2 检索方式 | 纯向量 vs 向量+BM25 混合（RRF 融合） | 混合检索对“精确名词题”（如 i茅台、酱香型）的提升 |
| E3 精排 | 加 bge-reranker 前后 | 精排对 context_precision 的提升与延迟代价 |
| E4 模型能力 | 本地 Qwen(4B~8B) vs DeepSeek API，同一套检索 | “检索质量 vs 模型能力”哪个是瓶颈；本地小模型+好 RAG 的天花板 |

每个实验跑完把指标写入 `results/`，最终合成一张总对比表 + 若干柱状图，直接进报告和 README。

## 七、LaTeX 报告方案（通俗中文 + 图表）

`report/report.tex`（ctexart 文档类），章节：
1. 我们要解决什么问题（价值主张、给谁用）
2. RAG 是什么（五步流程图，生活化类比）
3. 数据长什么样、难在哪（跨页表格病例截图、切块示意图）
4. 系统怎么搭（架构图 + 各组件选型理由）
5. 实验与结果（对比表 + 柱状图 + 典型 badcase 逐例分析）
6. 边界与结论（不能做什么、无答案题表现、下一步）
附录：复现指南（环境、命令）

图表清单：五步流程图、系统架构图、切块策略示意图（matplotlib 生成 PNG）、评测指标对比柱状图 2~3 张、badcase 汇总表。行文要求：每节先一句话结论，再展开；术语首次出现给大白话解释。

## 八、Subagent 选择性启用点

- **general-purpose**：黄金问答集起草；独立实验（E1/E2/E3 配置互不依赖时）并行执行与汇总；报告章节初稿并行起草
- **pdf:visual-judge**：报告 PDF 编译后的页面视觉验收（唯一视觉关口）
- **Explore**：已完成环境探查；后续如需大范围查代码再用
- 其余工作主线由主会话直接完成，不为小事开子代理

## 九、风险与备选

- `qwen3.5:2b` 在 Ollama 库中不存在 → 换 `qwen3:4b` / `qwen2.5:7b-instruct`（执行时以 `ollama pull` 实际结果为准）
- tectonic 首次编译联网拉宏包失败 → 备选安装 MiKTeX
- torch CPU 版若 embedding 速度不可接受 → 升级 cu128 轮子（RTX 5070 需 CUDA 12.8+）
- ragas 依赖链较重，安装冲突 → 固定版本组合，必要时降级为手写指标脚本
- 本地小模型生成质量弱 → 这本身就是 E4 的实验素材，不是失败

## 十、验证方式

- 阶段 1：验收问题实测（答对+出处正确+无答案题拒答）
- 阶段 2：用户逐题核对黄金集（人工把关，AI 只起草）
- 阶段 3/4：评测脚本可重复运行，分数落盘 `results/*.json`，图表由脚本从 json 生成而非手填
- 阶段 6：tectonic 编译成功 → 页面渲染 PNG → visual-judge 通过 → 交付 PDF
- 全程代码改动用 diff 自查；最终交付前汇总验收结果如实报告

执行顺序：阶段 0→1→2→3→4→5→6，其中阶段 2 出题、报告章节草稿、独立实验可在主线推进时选择性并行派发子代理。
